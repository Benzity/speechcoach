## 1. 한눈에 보는 서비스

**SpeechCoach AI**는 AI 모의면접 코칭 서비스다. 사용자가 이력서와 관심 직무를 입력하면:

1. **Claude(LLM)** 가 이력서 기반 맞춤 면접 질문을 생성하고,
2. 브라우저에서 **웹캠으로 답변을 녹화**하면,
3. 서버가 **음성 전사(Whisper) + 시선·자세 분석(MediaPipe) + 음향 분석(librosa)** 을 수행해,
4. **언어적(내용) + 반언어적(속도·어조·필러워드) + 비언어적(시선·자세) 피드백**을 종합 리포트로 제공한다.

한 문장 요약: **"면접 답변을 '내용'만이 아니라 '전달'까지 정량 분석해 코칭하는 서비스"**.

핵심 차별점 — 단순 GPT 래퍼가 아니다:

- LLM은 질문 생성·피드백 작성 2곳에만 쓰이고, **정량 분석(전사·시선·음향·필러)은 전부 로컬 ML 파이프라인**이 수행한다.
- LLM에는 원시 영상이 아니라 **우리 파이프라인이 산출한 정량 지표**가 들어간다. LLM은 숫자를 해석하는 코치 역할.
- 개인정보보호법 대응(암호화 저장·자동 파기·동의 관리)을 문서가 아니라 **코드와 97개 테스트로 강제**했다.

## 2. 시스템 아키텍처

```
[사용자 브라우저]
  React 19 SPA (Vite 8, TypeScript, Tailwind v4)
  - MediaRecorder로 webm 녹화(영상+음성)
  - speechSynthesis로 질문 TTS 낭독
  - recharts로 결과 시각화
  - 자체 구현 i18n (KO/EN)
        │  HTTPS (Bearer JWT)
        ▼
[Netlify] ─302 redirect─▶ [ngrok 터널] ─▶ [FastAPI 서버 (단일 프로세스)]
                                             │
        ┌────────────────────────────────────┼──────────────────────────┐
        │                                    │                          │
   [REST API 계층]                    [분석 워커 큐]                [백그라운드]
   - 인증(JWT+bcrypt)             ThreadPoolExecutor(1)           - 보유기간 파기 데몬
   - 세션/질문/업로드/결과          질문당 1작업, 직렬 처리            (6시간마다)
   - 레이트리밋(지수 백오프)              │                       - 접속기록 미들웨어
   - 라우터 default-deny 인증       ┌─────┴──────┐
        │                          ▼            ▼
        │                    [ffmpeg 음성추출]  (영상 복호화 → 임시파일)
        │                          │
        │                    [Whisper ASR] ── 전사문 + 타임스탬프 세그먼트
        │                          │
        │                 ┌────────┴────────┐  (병렬, ThreadPool(2))
        │                 ▼                 ▼
        │           [MediaPipe 비전]   [librosa 음향]
        │           시선/자세/손떨림    피치/속도/침묵/음량
        │                 └────────┬────────┘
        │                          ▼
        │                  [필러워드/버벅임 감지]
        │                          │
        ▼                          ▼
   [SQLite (WAL)] ◀──── 분석 결과 JSON 저장
   [암호화 영상 저장소]  AES-256-GCM (.webm)
        │
        ▼
   [Claude API (Anthropic)]  ← 세션 생성 시(질문), 세션 종료 시(피드백) 총 2회 호출
```

- **저장소**: SQLite(WAL 모드) + 파일시스템(암호화 영상). 별도 DB 서버 없음 — §9에서 이유 설명.
- **큐**: 인메모리 `ThreadPoolExecutor(max_workers=1)`. 작업 상태는 DB에 영속화되어 서버 재시작 시 `queued/processing` 상태를 재큐잉한다 (`main.py:_recover_stuck_analyses`).
- **배포(시연)**: Mac mini에서 FastAPI가 프론트 빌드(dist)까지 같이 서빙 → ngrok 터널로 외부 공개 → Netlify 도메인은 ngrok으로 302 리다이렉트. 브라우저는 ngrok 도메인 하나만 보므로 same-origin이 되어 CORS 문제가 없다.

## 3. 기술 스택 전체 목록

### 프론트엔드 (`frontend/`)

| 기술 | 버전 | 용도 |
|---|---|---|
| React | 19.2 | UI. 함수형 컴포넌트 + 훅만 사용 |
| TypeScript | 6.0 | 전체 타입 안전성 |
| Vite | 8.0 | 빌드/개발 서버. dev proxy로 `/api` → 백엔드 |
| Tailwind CSS | 4.3 | 스타일. `@tailwindcss/vite` 플러그인 방식 (config 파일 없음) |
| react-router-dom | 7.15 | SPA 라우팅 (8개 라우트 + 처리방침) |
| recharts | 3.8 | 결과 페이지 차트 (점수 레이더, 시선 파이, SPM 바 차트 등) |
| **브라우저 API** | - | `MediaRecorder`(webm 녹화), `getUserMedia`(카메라/마이크), `speechSynthesis`(질문 TTS), `AudioContext`(마이크 레벨 미터), `localStorage`(토큰·로케일) |
| i18n | 자체 구현 | 라이브러리 없이 `useSyncExternalStore` 기반. 10개 네임스페이스, ko/en 403+ 키 |

### 백엔드 (`backend/`)

| 기술 | 용도 |
|---|---|
| FastAPI + uvicorn | REST API. Pydantic 스키마로 요청/응답 검증 |
| SQLAlchemy 2.0 (Mapped) | ORM. 모델 5개: User/Session/Question/Analysis/Feedback |
| SQLite | 저장소. `WAL` + `foreign_keys=ON` + `secure_delete=ON` PRAGMA |
| **faster-whisper** | 음성 전사(ASR). CTranslate2 기반 Whisper 재구현 |
| **MediaPipe** (FaceMesh/Pose/Hands) | 시선(홍채)·자세(어깨/척추)·손 떨림 분석 |
| **librosa** | 음향 분석: pyin 피치 추적, RMS 음량, 무음 구간 분리 |
| ffmpeg / ffprobe | webm → 16kHz mono wav 추출, 영상 길이 측정 |
| OpenCV (cv2) | 영상 프레임 디코딩 (MediaPipe 입력) |
| **anthropic SDK** | Claude API 호출 (질문 생성 + 피드백 생성) |
| pdfplumber | 이력서 PDF 텍스트 추출 |
| bcrypt | 비밀번호 단방향 해시 (cost 12) |
| PyJWT | JWT 발급/검증 (HS256, 7일 TTL, 토큰 세대 `tv` 클레임) |
| **cryptography** (AESGCM) | 답변 영상 저장 암호화 (AES-256-GCM) |
| pytest | 백엔드 테스트 97개 |

### AI 모델

| 모델 | 역할 | 설정 |
|---|---|---|
| **Claude Sonnet** (`claude-sonnet-4-6`) | 질문 생성, 종합 피드백 | `max_tokens=4096`, 시스템 프롬프트 ko/en 분기, JSON 강제 출력 |

## 4. 엔드투엔드 시나리오 (구체 예시)

> "백엔드 개발자 지망생 김지원 님이 질문 5개짜리 한국어 모의면접을 본다"를 따라간다.

### ① 회원가입 (`POST /api/auth/signup`)

김지원 님이 이메일·비밀번호·생년월일을 입력하고 **필수 동의 2종**(개인정보 수집·이용 / 국외이전)에 체크한다.

서버에서 일어나는 일 (순서대로):
1. 생년월일로 **만 14세 이상 검증** → 통과하면 생년월일은 **버리고** `age_verified_at` 시각만 저장 (개인정보 최소수집)
2. 비밀번호 정책 검증: 8자 이상 + **흔한 비밀번호 253개 목록 차단** (복잡도 규칙은 NIST 권고에 따라 없음 — 길이가 왕)
3. 동의 2종 미체크 시 400 거부. 체크 시 `consented_at`, `consent_version`(방침 버전 날짜) 기록
4. 비밀번호는 **bcrypt(cost 12)** 로 해시 — 원문은 어디에도 저장되지 않음
5. JWT 발급: `{sub: user_id, tv: 0, exp: 7일}` — `tv`(token_version)는 로그아웃 시 서버측 무효화에 사용

### ② 면접 설정 (온보딩, `POST /api/sessions`)

관심 직무 "백엔드 개발자", 이력서 텍스트(또는 PDF 10MB 이하), 질문 개수 5(슬라이더 3~15), **면접 언어 한국어/영어 선택**, 선택적으로 목표 회사 프리셋(삼성전자·네이버·토스 등 7개 — 선택하면 인재상 자동 입력).

서버에서:
1. 검증: 질문 3~15개, 언어 `ko|en`, 이력서 텍스트 50,000자 / PDF 10MB 상한
2. PDF면 pdfplumber로 텍스트 추출
3. **PII 마스킹**: 주민등록번호·전화번호·이메일·주소·생년월일을 정규식으로 `[전화번호]` 같은 플레이스홀더로 치환. **마스킹본이 LLM으로 전송되고 DB에도 마스킹본만 저장**된다
4. **Claude 호출 1회**: 시스템 프롬프트("당신은 시니어 면접관…") + 직무/이력서/인재상 → JSON으로 질문 5개(각각 `text`, `category`, `intent`) 생성. 코드펜스 제거 → JSON 파싱 → 개수/형식 검증 후 저장. 실패 시 502와 사용자 친화적 한국어 에러
5. 세션·질문 5행 DB 저장, 상태 `created`

예시 생성 질문: *"이력서에 결제 API 개선 경험이 있는데, 트래픽이 몰릴 때 정합성을 어떻게 보장했나요?"* (category: `experience`, intent: "실무 문제 해결 깊이 검증")

### ③ 면접 진행 (`/interview/:id`)

1. `getUserMedia`로 카메라·마이크 권한 요청 (거부 시 데모 모드로 진행 가능)
2. 질문이 화면에 타자기 효과로 표시되며 **speechSynthesis가 낭독** — 면접 언어에 따라 `ko-KR`(rate 0.92) / `en-US`(rate 1.0) 보이스 자동 선택
3. 3초 카운트다운 → `MediaRecorder`가 webm(VP8+Opus) 녹화 시작
4. **답변 제한 60초** (10초 전 WARN, 5초 전 CRITICAL 표시). 5초 미만 답변은 confirm으로 재확인
5. "다음" 클릭 → 녹화 Blob을 `POST /api/sessions/{id}/answers/{q_index}`로 **백그라운드 업로드**(실패 시 3회 재시도) — 사용자는 기다리지 않고 바로 다음 질문으로
6. 서버는 업로드 스트림을 **1MB 청크로 읽으며 200MB 상한 검사와 동시에 AES-256-GCM 암호화**해 디스크에 쓴다 (평문이 디스크에 닿지 않음) → 분석 큐에 등록 (202 Accepted)

### ④ 분석 (백그라운드, 질문당 1작업 직렬)

각 질문 영상에 대해 `pipeline.py`가 실행하는 순서:

```
암호화 영상 복호화 → 임시 평문 파일 (분석 도구들이 파일 경로를 요구하므로)
  → ffmpeg: 음성만 16kHz mono wav로 추출
  → Whisper ASR: 전사문 + 세그먼트(문장별 시작/끝 타임스탬프)
  → [병렬] MediaPipe 비전 ∥ librosa 음향
  → 필러워드/버벅임 카운트 + 타임스탬프 이벤트
  → 결과 JSON을 analyses 테이블에 저장, 상태 completed
  → finally: 임시 평문 파일들 덮어쓰기 삭제(secure delete)
```

김지원 님의 3번 답변에서 나온 실제 형태의 결과 예:

```json
{
  "verbal_metrics": {
    "spm": 287.3,                    // 음절/분 — 약간 빠름
    "pitch_mean": 128.4, "pitch_std": 22.1,
    "monotone_index": 0.17,          // 낮을수록 단조로움
    "long_silences_count": 2,        // 1.5초 이상 침묵 2회
    "silence_events": [{"t": 12.3, "dur": 2.1}, {"t": 31.0, "dur": 1.8}],
    "fillers": {"어": 4, "음": 2, "약간": 1},
    "stutter_count": 1,
    "filler_events": [{"t": 3.2, "label": "어"}, ...]
  },
  "nonverbal_metrics": {
    "gaze_distribution": {"camera": 0.72, "down": 0.19, "left": 0.05, ...},
    "gaze_off_events": [{"t": 14.0, "dur": 2.4, "dir": "down"}],
    "posture": {"shoulder_asymmetry": 0.021, "spine_alignment": 0.94},
    "hand_tremor_index": 1.3
  }
}
```

### ⑤ 대기 화면 (`/processing/:id`)

프론트가 1.5초마다 `analysis-status`를 폴링(질문별 queued/processing/completed/failed 집계). 대기 중 취업 팁 7개가 10초마다 로테이션. 전부 끝나면 자동으로 피드백 생성을 트리거.

### ⑥ 종합 피드백 (`POST /api/sessions/{id}/feedback`, 동기 5~15초)

1. 질문 5개의 전사문 + 정량 지표 전체를 모아 **Claude 호출 1회**
2. 프롬프트 설계 포인트:
   - "정량 데이터를 나열하지 말고 인사이트로 변환하라"
   - **ASR 오인식 방어 지침**: "전사 오류(영어 용어 음차 등)는 답변자 잘못이 아니므로 감점 근거로 삼지 마라"
   - 비디오 분석 데이터가 없으면(데모 모드) `nonverbal 점수는 반드시 null` — 추측 점수 금지
   - 침묵 1~2회는 정상 범주이니 과도하게 지적하지 말 것
3. 응답 JSON: `overall_summary`, `scores{content, nonverbal, verbal, overall}`, `critical_issues[]`, `verbal_feedback`, `nonverbal_feedback`, `practice_tips[]`, `positive_points[]` — 필수 키 검증 후 저장

### ⑦ 결과 페이지 (`/result/:id`)

- 종합 점수 카드 + recharts 시각화 (시선 분포 파이, 질문별 SPM 바, 필러 빈도)
- **감점 타임라인**: "0:14 시선 이탈(아래, 2.4초)", "0:03 필러워드 '어'" — 영상 재생 위치와 연동
- 답변 영상 다시보기: `<video>`는 Authorization 헤더를 못 보내므로 **인증된 fetch로 blob을 받아 `URL.createObjectURL`** 재생. 서버는 암호화 파일을 **복호화 스트리밍**으로 응답
- 모든 AI 생성 콘텐츠에 "AI 생성" 배지 표시 (AI기본법 제31조 표시 의무)

## 5. 핵심 파이프라인 상세

### 5.1 질문 생성 (`services/question_generator.py`)

- Claude에 **시스템 프롬프트**(면접관 페르소나 + 생성 원칙 5개: 실무 중심 / 이력서 파고들기 / 인성 1~2개 / 표면 지식 지양 / 언어 지정)와 **유저 프롬프트**(직무·인재상·이력서 + JSON 스키마)를 전달.
- LLM 출력 방어 3겹: ① 코드펜스(\`\`\`json) 제거 → ② `json.loads` 실패 시 사용자 친화 에러 → ③ 질문 개수·필드 형식 검증. 초과 생성은 잘라 쓰고, 부족하면 재시도 요청 에러.
- 면접 언어(ko/en)에 따라 **시스템·유저 프롬프트 전체가 분기**된다 (번역이 아니라 각 언어로 네이티브하게 작성).

### 5.2 ASR (`workers/asr_worker.py`)

- **faster-whisper** 사용: OpenAI whisper 대비 동일 정확도에 최대 4배 빠름(CTranslate2 최적화). 모델은 프로세스당 1회만 로드해 싱글턴 캐싱.
- `beam_size=1`(greedy) — 속도 우선. `language` 파라미터를 세션의 면접 언어로 지정해 **언어 자동감지 오류를 원천 차단**.
- 반환: 전체 전사문 + 세그먼트별 `{start, end, text}` — 이 타임스탬프가 필러워드 이벤트·감점 타임라인의 기반이 된다.
- 환경변수로 모델 크기·디바이스 전환: GPU 서버는 `large-v3`/CUDA/float16, 시연용 Mac은 `small`/CPU/int8.

### 5.3 비전 분석 (`workers/vision_worker.py`)

- 영상을 **5fps로 샘플링** (모든 프레임 분석은 낭비 — 시선·자세는 초당 5회면 충분, NFR로 명시)
- **시선(핵심)**: MediaPipe FaceMesh `refine_landmarks=True`로 **홍채 중심 랜드마크(468, 473)** 를 얻고, 눈 코너(33/133, 263/362) 사이에서 홍채의 상대 위치(0~1)를 계산. 정면이면 ~0.5, **5% 이상 벗어나면** camera/down/up/left/right로 분류. 양안 평균 사용.
  - 머리 방향이 아니라 **눈동자 위치** 기반이라, 고개는 고정하고 눈만 굴려도 잡아낸다.
  - 0.6초 미만의 순간 이탈은 이벤트에서 제외 (깜빡임·미세 흔들림 오탐 방지)
- **자세**: Pose 랜드마크로 어깨 좌우 높이차(`shoulder_asymmetry`)와 코-어깨중심 정렬(`spine_alignment`) 산출
- **손 떨림**: 손목 좌표의 표준편차 → 0~10 지수화
- 얼굴·자세·손이 전부 미감지면 **빈 dict 반환** → 피드백 단계에서 "비언어 평가 불가"로 정직하게 처리 (0점 오판 방지)

### 5.4 음향 분석 (`workers/audio_worker.py`)

- `librosa.pyin`으로 프레임별 기본주파수(F0) 추적 (C2~C7 범위) → 평균 피치, 표준편차, **monotone_index = std/mean** (낮을수록 단조로운 목소리)
- `librosa.effects.split(top_db=30)`으로 발화/무음 구간 분리 → **1.5초 이상** 무음만 "긴 침묵"으로 카운트 (0.5초는 정상 호흡이라 과다 보고됨 — 실측으로 튜닝한 값)
- **SPM(음절/분)** = 음절 수 ÷ 실발화 시간 × 60. 침묵을 빼고 나누는 게 포인트 — 말이 빠른데 침묵이 길면 WPM류 지표는 평균의 함정에 빠진다.
  - 한국어: 한글 1글자 = 1음절 (한국어는 음절 단위 언어라 정확)
  - 영어: 단어별 **모음군(vowel group) 개수**로 음절 추정 (`beautiful` → eau/i/u = 3음절)

### 5.5 필러워드 감지 (`services/filler_detector.py`)

- 한국어 필러 21개("어", "음", "그러니까", "약간"…) + 영어 17개("um", "like", "you know"…)
- **오탐 방지가 핵심 설계**: "어"를 substring으로 찾으면 "**어**려운", "**어**떻게"가 전부 잡힌다. 그래서:
  1. 다어절 필러("그 뭐지")를 먼저 매칭하고 텍스트에서 소비(이중 카운트 방지)
  2. 1글자 필러는 **어절(공백 단위 토큰) 완전 일치**일 때만 카운트
  3. 영어는 `\b` 단어 경계 정규식 ("so"가 "**so**lution"에서 안 잡힘)
  4. 일상어 빈도가 너무 높은 "네/솔직히/사실" 등은 사전에서 제외 (실사용 피드백으로 튜닝)
- 버벅임: 같은 단어 연속 2회 이상 반복(`그 그 그래서`)을 정규식으로 감지
- ASR 세그먼트별로 돌려 **타임스탬프 이벤트**(`{t: 3.2, label: "어"}`)도 생성 → 결과 페이지 타임라인

### 5.6 파이프라인 안정성 설계

- 각 워커(ASR/Vision/Audio)는 `_safe()` 래퍼로 격리 — **하나가 죽어도 나머지 결과는 저장** (부분 성공)
- 큐는 인메모리지만 **작업 상태는 DB가 진실**: 서버 재시작 시 `queued/processing` 행을 찾아 재큐잉
- 피드백 생성 중 예외 발생 시 세션을 `failed`로 전환해 "analyzing 좀비 상태" 방지

## 6. 분석 지표 사전

| 지표 | 정의 | 산출 방법 | 판정 참고 |
|---|---|---|---|
| `spm` | 발화 속도 (음절/분) | 음절 수 ÷ 실발화 시간 × 60 | 한국어 안정권 대략 240~300 |
| `pitch_mean/std` | 목소리 높이 평균/변화량 (Hz) | librosa pyin | - |
| `monotone_index` | 억양 다양성 | pitch_std ÷ pitch_mean | 낮으면 단조로움 |
| `rms_mean` | 평균 음량 | librosa RMS | 상대 비교용 |
| `long_silences_count` | 1.5초 이상 침묵 횟수 | 무음 구간 gap 분석 | 1~2회는 정상 |
| `silence_events` | 침묵 타임스탬프 | `{t, dur}` 목록 | 타임라인 표시 |
| `fillers` | 필러워드별 빈도 | 어절 정확 매칭 | §5.5 |
| `stutter_count` | 연속 반복(버벅임) | 정규식 | - |
| `gaze_distribution` | 시선 방향 비율 | 홍채 위치, 5fps | camera 비율이 핵심 |
| `gaze_off_events` | 0.6초 이상 시선 이탈 | 연속 구간 병합 | 타임라인 표시 |
| `shoulder_asymmetry` | 어깨 기울기 | 좌우 어깨 y좌표 차 | 낮을수록 반듯 |
| `spine_alignment` | 상체 정렬 | 코와 어깨 중심 거리 | 1에 가까울수록 정렬 |
| `hand_tremor_index` | 손 움직임 산만도 | 손목 좌표 분산, 0~10 | - |

LLM 점수 4종(content/verbal/nonverbal/overall, 0~100)은 위 지표 + 전사문을 근거로 Claude가 산정하되, **비전 데이터가 없으면 nonverbal은 강제 null**.

## 7. 다국어 지원 (UI + 면접 언어)

두 축이 **독립적**이다:

1. **사이트 UI 언어 (KO/EN)** — 헤더 토글. i18n 라이브러리 없이 자체 구현:
   - `useSyncExternalStore` 기반 전역 로케일 스토어 (Provider 불필요, 모든 컴포넌트 자동 리렌더)
   - 네임스페이스별 사전 파일 10개(auth/common/errors/…/privacy), ko/en 각 403+ 키
   - `en: Record<keyof typeof ko, string>` 타입으로 **키 누락을 컴파일 타임에 잡음**
   - `{name}` 플레이스홀더 보간, localStorage 저장, `<html lang>`·문서 제목 동기화
   - React 밖(api.ts 에러 메시지)에서도 같은 `t()` 사용 가능
2. **면접 언어 (ko/en)** — 온보딩에서 선택, 세션 DB에 저장. 이 값 하나가 파이프라인 전체를 분기:
   - Claude 질문 생성/피드백 프롬프트 (각 언어 네이티브 프롬프트)
   - Whisper `language` 파라미터 (자동감지 대신 명시)
   - 필러 사전 선택 (en이면 한국어 사전 스킵)
   - SPM 음절 계산 방식 (한글 글자 수 vs 모음군)
   - 브라우저 TTS 보이스·속도 (`ko-KR` 0.92 / `en-US` 1.0)

왜 라이브러리(i18next)를 안 썼나: 13개 파일 규모 SPA에 의존성 추가 대비 이득이 없었고, 자체 구현이 120줄로 끝났으며 타입 안전성은 오히려 더 좋다.

## 8. 보안·개인정보 구현

### 8.1 저장 데이터별 보호 수준

| 데이터 | 보호 방식 | 근거 |
|---|---|---|
| 비밀번호 | **bcrypt 해시 (cost 12)** — 복호화 자체가 불가능 | 안전성 확보조치 기준 제7조(의무) |
| 답변 영상 (얼굴·음성) | **AES-256-GCM 저장 암호화** | 생체인식정보 해당 여부가 다투어질 수 있어 **유리한 해석에 기대지 않고 암호화** (법적 최소선 초과) |
| 주민번호·카드번호 | **애초에 수집하지 않음** | 최소수집 원칙 |
| 이력서 | PII 5종 자동 마스킹 후 저장·전송 | 제16조 최소수집 |
| 이메일·전사문 등 | 평문 (암호화 의무 비대상) + 접근통제·접속기록 | - |

### 8.2 영상 암호화 상세 (`services/video_crypto.py`)

- **AES-256-GCM, 1MB 청크 단위** 독립 암호화. 파일 구조: `SCV1 매직(4B) ∥ [nonce 12B ∥ 암호문 ∥ 인증태그 16B] × N`
- **왜 청크인가**: GCM 인증 태그는 메시지 전체에 대해 계산되므로 통짜 암호화면 200MB를 통째로 메모리에 올려야 검증 가능. 청크 방식은 **일정한 메모리로 스트리밍 암·복호화**가 된다.
- 청크마다 nonce 새로 생성 → GCM의 치명적 실패 모드인 nonce 재사용 원천 차단
- **업로드 경로에서 평문이 디스크에 닿지 않는다**: HTTP 스트림 → (크기 검사) → 암호화 → 디스크
- 재생은 복호화 스트리밍(임시 파일 없음). 분석만 임시 평문 파일이 필요(ffmpeg가 파일 경로 요구)하고, 끝나면 **0으로 덮어쓴 후 삭제**
- 키는 `VIDEO_ENCRYPTION_KEY` 환경변수(base64 32바이트), JWT 키와 **용도별 분리**. 키가 없으면 서버가 아예 안 뜸(fail-closed)
- 한계도 명시: 키가 같은 서버에 있으므로 서버 자체 침해는 못 막는다 — 이 암호화의 방어 대상은 **디스크·백업 매체 유출**

### 8.3 인증·접근 통제

- **JWT + token_version**: JWT는 본래 취소 불가 → DB에 `token_version`을 두고 클레임 `tv`와 대조. 로그아웃/탈퇴 시 버전 증가 → **탈취된 토큰도 즉시 무효**
- **로그인 레이트리밋**: 계정축 + IP축 2축, 5회 무료 후 지수 백오프(1s→2s→4s… 상한 15분, 1시간 후 자연 회복). 영구 잠금을 안 쓰는 이유: 공격자가 남의 계정을 일부러 잠그는 DoS(악의적 계정 잠금, ASVS 6.1.1) 방지
- **default-deny 라우트 가드**: 부팅 시 전체 라우트를 스캔해 "공개 목록에 없는데 인증도 없는" 엔드포인트가 있으면 **서버가 뜨지 않음**. 새 엔드포인트에서 인증을 깜빡하는 실수를 배포 전에 잡는다
- 모든 세션 조회는 소유자 검증 — 남의 세션은 403이 아니라 **404** (존재 여부도 숨김)

### 8.4 개인정보 라이프사이클

- **동의**: 가입 시 수집·이용 + 국외이전(Claude API가 미국 소재) **별도 동의**, 버전·시각 기록. 만 14세 확인 후 생년월일 즉시 폐기
- **보유기간 자동 파기**: 데몬 스레드가 6시간마다 스윕 — 영상 30일, 분석 결과 6개월 경과분을 **덮어쓰기 파기**. 탈퇴 시 전체 즉시 삭제 + SQLite VACUUM
- **복원 불가 파기**: 파일을 0으로 덮어쓴 후 삭제(NIST SP 800-88 기준 1회면 충분) + DB는 `secure_delete=ON` PRAGMA
- **접속기록**: 인증된 개인정보 접근 전부를 미들웨어가 기록, **2년 보관**(영상의 민감정보 해당 가능성 때문에 법정 1년에서 상향), 월 1회 점검 스크립트 + 유출 시 72시간 신고 대응 스크립트 구비
- **AI 투명성**: 모든 AI 생성물에 배지 표시, "점수는 채용 결과를 예측하지 않는다" 고지 (AI기본법 제31조)

## 9. 아키텍처 결정과 트레이드오프

정직하게 말할 수 있는 게 강점이다. "왜 이렇게 했나 + 규모가 커지면 어떻게 바꿀 것인가"를 세트로 준비했다.

| 결정 | 이유 | 규모 확장 시 |
|---|---|---|
| **SQLite** (DB 서버 없음) | 단일 서버 + 쓰기 빈도 낮음. WAL 모드로 읽기 동시성 확보. 운영 복잡도 0 | PostgreSQL로 이관 (SQLAlchemy라 코드 변경 최소) |
| **인메모리 큐 (워커 1)** | GPU 1장에서 Whisper 동시 실행은 오히려 느려짐 → 직렬이 최적. 상태는 DB 영속화로 유실 방지 | Redis + Celery/RQ, GPU 워커 수평 확장 |
| **분석은 비동기, 피드백은 동기(5~15초)** | 분석은 질문마다 오래 걸려 폴링 UX, 피드백은 1회라 대기 화면에서 동기 처리 | 피드백도 작업 큐로 |
| **모놀리스 1프로세스** | 시연·초기 단계에서 마이크로서비스는 순수 오버헤드 | API 서버 / GPU 분석 워커 분리가 1순위 |
| **LLM에 정량 지표를 주입** (영상을 직접 넣지 않음) | 비용·속도·재현성. 점수 근거가 우리 파이프라인 수치라 설명 가능 | 멀티모달 LLM 보조 검증 추가 검토 |
| **브라우저 TTS** (ElevenLabs 대신) | 무료·지연 0·서버 부하 0. ElevenLabs 연동 코드는 있으나 무료 쿼터 소진으로 비활성 | 유료 TTS 재활성화 |
| **ngrok + Netlify 리다이렉트** | GPU가 달린 로컬 머신을 외부 공개하는 가장 단순한 방법. same-origin이라 CORS 없음 | 클라우드 GPU 인스턴스 + 정식 도메인 |
| **레이트리밋 인메모리** | 단일 프로세스라 충분. 코드에 한계 명시 | 멀티 워커 시 Redis 공유 저장소 |

성능 감각 (질문 1개, 60초 답변 기준):
- ffmpeg 추출 ~1초 / Whisper: GPU large-v3 수 초, CPU small 수십 초 / MediaPipe: 5fps 샘플링으로 실시간의 1/6 수준 프레임만 처리 / librosa ~2초
- 답변 녹화하는 동안 이전 질문이 분석되므로 **체감 대기는 마지막 1~2문항 분량**

## 11. 예상 질문과 답변 (Q&A)

### A. AI / LLM

**Q1. 그냥 GPT 래퍼 아닌가요? 직접 만든 게 뭔가요?**
> LLM이 하는 일은 "질문 문장 만들기"와 "종합 코멘트 쓰기" 2가지뿐입니다. 서비스의 몸통인 **정량 분석 — 음성 전사, 홍채 기반 시선 추적, 자세 판정, 발화 속도·침묵·필러워드 감지 — 는 전부 저희가 로컬 ML 파이프라인으로 직접 구현**했습니다. 오탐을 잡기 위한 어절 단위 필러 매칭, 침묵 1.5초 임계값, 시선 이탈 0.6초 필터 같은 것들은 실측으로 튜닝한 저희 로직입니다. LLM에는 이 지표들이 입력으로 들어가고, LLM은 숫자를 해석하는 코치 역할만 합니다.

**Q2. 왜 Claude를 썼나요?**
> 한국어 생성 품질과 **JSON 스키마 준수율**이 좋았고, 긴 이력서+지표 전체를 넣어도 컨텍스트가 충분했습니다. 다만 특정 벤더 종속을 최소화하려고 호출부를 서비스 모듈로 분리해뒀고, 프롬프트와 파싱 로직만 맞추면 교체 가능합니다.

**Q3. LLM이 이상한 답(할루시네이션)을 주면요?**
> 3겹 방어입니다. ① 출력을 JSON으로 강제하고 코드펜스 제거 후 파싱, ② 필수 키·개수·형식 검증 실패 시 저장하지 않고 사용자에게 재시도 안내, ③ 프롬프트 수준에서 "비전 데이터 없으면 비언어 점수는 반드시 null", "ASR 오인식을 감점 근거로 쓰지 마라" 같은 **금지 규칙**을 명시합니다. 점수의 근거가 되는 수치 자체는 LLM이 아니라 저희 파이프라인이 만든 값이라 조작·창작의 여지가 작습니다.

**Q4. ASR이 잘못 받아적으면 피드백도 틀리지 않나요?**
> 실제로 겪은 문제입니다. "query source"가 "퀄리소스"로 전사되는 식인데, 피드백 프롬프트에 **"전사 오류는 답변자 잘못이 아니므로 지적·감점 금지, 불분명한 구간은 평가 보류"** 지침을 넣어 방어합니다. 또 면접 언어를 세션에 저장해 Whisper에 언어를 명시하므로 언어 자동감지 오류는 원천 차단됩니다.

**Q5. API 비용은요?**
> 세션당 Claude 호출은 **정확히 2회**(질문 생성 1 + 피드백 1)로 설계했습니다. 질문당 호출하지 않습니다. 영상·음성을 LLM에 보내지 않고 텍스트 지표만 보내는 것도 비용 통제 장치입니다.

### B. 음성 인식 (Whisper)

**Q6. 왜 Whisper인가요? 왜 faster-whisper인가요?**
> 한국어를 포함한 다국어 오픈소스 ASR 중 정확도가 검증된 표준이고, **로컬 실행이라 음성이 전사 목적으로 외부에 나가지 않습니다**(개인정보 관점 장점). faster-whisper는 같은 모델을 CTranslate2로 재구현한 것으로 동일 정확도에 최대 4배 빠릅니다. 모델 크기·디바이스는 환경변수로 전환합니다 — GPU 서버는 large-v3/float16, 시연 노트북은 small/int8.

**Q7. 실시간 전사는 왜 안 했나요?**
> 실시간 자막이 필요한 서비스가 아닙니다. 답변이 끝난 뒤 배치 전사가 정확도도 높고(문맥 전체 사용), 면접 중 사용자 기기 부하도 없습니다. 답변 녹화 중에 이전 답변이 백그라운드에서 분석되므로 체감 대기도 짧습니다.

### C. 비전 분석

**Q8. 시선 추적은 어떻게 하나요? 시선 추적 장비 없이 되나요?**
> 일반 웹캠만으로 합니다. MediaPipe FaceMesh의 refine 모드가 **홍채 중심 랜드마크**를 제공하는데, 홍채가 눈의 좌우 코너 사이 어디에 있는지 비율(정면이면 0.5)을 양쪽 눈 평균으로 계산합니다. 5% 이상 벗어나면 상하좌우로 분류합니다. 머리 방향이 아니라 **눈동자 위치** 기반이라 고개를 고정하고 눈만 굴려도 잡습니다. 깜빡임 같은 0.6초 미만 이탈은 노이즈로 버립니다.

**Q9. 왜 5fps만 분석하나요?**
> 시선·자세는 초당 5번이면 행동 패턴 파악에 충분하고, 전 프레임(30fps) 분석 대비 연산이 1/6입니다. 요구사항(NFR)으로 명시한 의도된 설계입니다.

**Q10. 표정 분석은요?**
> 현재 범위에서 뺐습니다. 표정→감정 추론은 정확도 논란과 편향 리스크가 커서, 근거가 명확한 지표(시선 비율, 어깨 기울기, 침묵 초 수)부터 제공하는 게 코칭 신뢰도에 낫다고 판단했습니다. 로드맵에는 있습니다.

### D. 음향·언어 분석

**Q11. 발화 속도를 왜 WPM이 아니라 SPM으로 재나요?**
> 한국어는 '단어' 경계가 조사·합성어 때문에 불안정하지만 **음절은 글자 수와 정확히 일치**합니다(음절 문자). 그래서 한국어는 음절/분(SPM)이 표준적입니다. 또 하나 중요한 게, 전체 시간이 아니라 **침묵을 뺀 실발화 시간**으로 나눕니다 — 빠르게 말하고 길게 침묵하는 사람이 '적당한 속도'로 위장되는 평균의 함정을 막기 위해서입니다. 영어 면접은 단어별 모음군 개수로 음절을 추정해 같은 지표를 유지합니다.

**Q12. "어"가 필러인지 "어려운"의 첫 글자인지 어떻게 구분하나요?**
> 초기 버전에서 실제로 터졌던 오탐입니다. 지금은 1글자 필러를 **어절(공백 단위) 완전 일치**일 때만 카운트합니다 — "어려운"은 어절이 "어려운"이라 안 잡히고, 단독 "어"만 잡힙니다. 다어절 필러("그 뭐지")를 먼저 소비해 이중 카운트를 막고, 영어는 단어 경계 정규식을 씁니다. 이 오탐 케이스들은 회귀 테스트로 고정해뒀습니다.

**Q13. 침묵 기준 1.5초는 어디서 나온 숫자인가요?**
> 처음엔 0.5초였는데 정상적인 호흡·쉼표까지 전부 "침묵"으로 보고돼서 실측 후 1.5초로 올렸습니다. 면접에서 듣는 사람이 불편함을 느끼기 시작하는 정적 길이 기준입니다. 그리고 피드백 프롬프트에도 "1~2회는 정상 범주"라고 명시해 과잉 지적을 막습니다.

### E. 보안·개인정보

**Q14. 얼굴 나오는 영상인데 어떻게 보관하나요?**
> **AES-256-GCM으로 암호화해 저장**합니다. 업로드 스트림을 받으면서 바로 암호화하므로 평문이 디스크에 닿지 않습니다. 법적으로 이 영상이 '생체인식정보'(암호화 의무 대상)인지는 처리 목적상 다툼의 여지가 있는데, **유리한 해석에 기대지 않고 암호화하는 쪽을 택했습니다**. 보유기간(30일)이 지나면 0으로 덮어쓴 뒤 삭제하는 복원 불가 파기를 자동 실행합니다.

**Q15. 왜 통짜 암호화가 아니라 1MB 청크 단위인가요?**
> GCM은 무결성 태그를 메시지 전체에 대해 계산해서, 파일 하나로 암호화하면 재생할 때 **200MB를 통째로 메모리에 올려야** 검증이 됩니다. 1MB 청크마다 독립 암호화(각자 nonce+태그)하면 일정한 메모리로 스트리밍 복호화가 되고, nonce를 청크마다 새로 뽑으니 GCM의 치명적 실패 모드인 nonce 재사용도 없습니다.

**Q16. 이력서 같은 민감한 텍스트가 미국(Claude)으로 나가는데요?**
> 세 가지로 대응합니다. ① 전송 전에 주민번호·전화·이메일·주소·생년월일을 정규식으로 자동 마스킹하고 **마스킹본만 전송·저장**합니다. ② 가입 시 국외이전을 **별도 항목으로 동의**받고 처리방침에 이전받는 자·항목·보유기간을 명시합니다(제28조의8). ③ Anthropic은 자사 정책상 API 입력을 모델 학습에 쓰지 않음을 밝히고 있습니다.

**Q17. JWT 탈취당하면요?**
> DB에 토큰 세대(token_version)를 두고 JWT 클레임과 대조합니다. 로그아웃·탈퇴 시 세대를 올리면 **이미 발급된 토큰 전부가 즉시 무효**가 됩니다. localStorage만 지우는 클라이언트 로그아웃의 한계를 서버측 무효화로 보완한 겁니다.

**Q18. 무차별 대입 공격은요?**
> 계정축+IP축 2축 레이트리밋입니다. 5회까지는 오타 배려로 허용하고 이후 지수 백오프(1초→2초→4초… 최대 15분)를 겁니다. 영구 잠금을 안 쓰는 이유가 중요한데, 공격자가 남의 이메일로 일부러 실패를 쌓아 **정상 사용자를 잠가버리는 DoS**(ASVS가 경고하는 malicious lockout)를 막기 위해서입니다. 시간이 지나면 자연 회복됩니다.

**Q19. 개발자가 인증 붙이는 걸 깜빡하면요?**
> 부팅 시 전체 라우트를 스캔해서 "공개 허용 목록에 없는데 인증 의존성도 없는" 엔드포인트가 발견되면 **서버가 아예 시작되지 않습니다**. default-deny를 코드로 강제한 거고, 이것도 테스트로 검증합니다.

### F. 아키텍처·확장성

**Q20. SQLite로 서비스가 되나요?**
> 현 단계(단일 서버, 낮은 쓰기 빈도)에선 최적입니다. WAL 모드로 읽기 동시성을 확보했고 운영 복잡도가 0입니다. 사용자가 늘면 PostgreSQL로 옮기는데, SQLAlchemy ORM이라 이관 비용이 낮습니다. "지금 규모에 맞는 선택 + 명확한 이관 경로"가 저희 원칙입니다.

**Q21. 동시에 여러 명이 면접 보면요?**
> API 요청 자체는 FastAPI가 동시 처리합니다. 무거운 건 GPU 분석인데, 분석 큐를 **의도적으로 워커 1개 직렬**로 뒀습니다 — GPU 1장에서 Whisper를 동시에 여러 개 돌리면 컨텍스트 스위칭으로 오히려 전체 처리량이 떨어지기 때문입니다. 대신 업로드 즉시 202를 반환하고 진행 상태를 폴링으로 보여주므로 사용자는 블로킹되지 않습니다. 확장 시엔 GPU 워커를 늘리고 Redis 큐로 교체합니다.

**Q22. 서버가 분석 도중 죽으면 작업이 유실되나요?**
> 큐는 인메모리지만 **작업 상태는 DB에 영속화**됩니다. 재시작 시 lifespan 훅이 queued/processing 상태로 남은 분석을 전부 찾아 재큐잉합니다. "큐는 휘발돼도 DB가 진실"이라는 설계입니다.

**Q23. 마이그레이션 도구(Alembic) 없이 스키마 변경은 어떻게?**
> 부팅 시 실행되는 경량 마이그레이션 함수가 있습니다. PRAGMA로 기존 컬럼을 조회해 없는 컬럼만 ALTER TABLE로 추가하고, 멱등이라 반복 실행해도 안전합니다. 테이블·컬럼명은 식별자 정규식으로 검증해 인젝션 여지를 차단합니다. 스키마 변경이 잦아지면 Alembic 도입이 맞고, 그 시점도 정해뒀습니다.

**Q24. 데모가 ngrok인데 프로덕션 계획은?**
> ngrok은 "GPU 달린 로컬 머신을 외부 공개"하는 시연용 선택입니다. 이때 ngrok이 TLS를 종료하는 국외 사업자라는 점까지 식별해서 **처리방침에 수탁자로 고지**해뒀습니다(놓치기 쉬운 부분인데 법무 검토에서 저희가 먼저 찾았습니다). 프로덕션은 클라우드 GPU 인스턴스 + 정식 도메인 + CORS 화이트리스트로 전환합니다.

### G. 프론트엔드

**Q25. 녹화는 어떻게 구현했나요?**
> 브라우저 표준 `MediaRecorder` API로 webm(VP8+Opus)을 녹화합니다. 서버 왕복 없이 클라이언트에서 인코딩되므로 서버 부하가 없고, 업로드는 백그라운드로 진행하며 실패 시 3회 재시도합니다. 사용자는 업로드를 기다리지 않고 다음 질문으로 넘어갑니다.

**Q26. 결과 페이지 영상 재생은 그냥 video src 아닌가요?**
> `<video src>`는 Authorization 헤더를 못 실어서 인증이 안 됩니다. 그래서 **인증된 fetch로 blob을 받아 `URL.createObjectURL`로 재생**합니다. 서버 쪽은 암호화 파일을 청크 단위로 복호화하며 스트리밍하고, 첫 청크를 미리 검증해 복호화 실패 시 200이 아니라 500이 나가도록 처리했습니다(제너레이터 지연 평가 함정을 리뷰에서 잡아 회귀 테스트까지 붙인 부분입니다).

**Q27. 상태 관리 라이브러리는 왜 없나요?**
> 서버 상태는 페이지별 fetch로 충분하고, 전역 상태는 인증(Context)과 로케일(useSyncExternalStore) 둘뿐입니다. 13개 파일 규모에서 Redux는 과설계라고 판단했습니다. "필요해질 때 넣는다"가 원칙입니다.

### H. 검증·품질

**Q28. 테스트는 어떻게 하고 있나요?**
> 백엔드 pytest **97개**가 인증·레이트리밋·암복호화·파기·PII 마스킹·필러 오탐까지 커버합니다. 특히 버그 수정 시 **수정 전 코드로 되돌려 테스트가 실제로 실패하는지 확인**하는 회귀 검증을 문화로 갖고 있습니다. 컴플라이언스도 문서로만 쓰지 않고 "고지한 내용이 코드에서 실제로 동작하는가"를 테스트로 강제합니다 — 예: 만 14세 미만 가입 차단, 평문 영상 500 응답, 보유기간 경과 파기.

**Q29. 분석 결과가 정확하다는 걸 어떻게 믿나요?**
> 지표별로 검증 방법이 다릅니다. 음절 카운트·필러 감지처럼 결정적인 로직은 단위 테스트로 고정하고, 시선·침묵처럼 임계값이 있는 것은 실제 녹화 영상으로 과탐/미탐을 보며 튜닝했습니다(침묵 0.5→1.5초, 시선 이탈 최소 0.6초 등). 그리고 사용자에게 점수만 주지 않고 **타임스탬프 근거**("0:14에 2.4초 시선 이탈")를 함께 보여줘서 사용자가 직접 검증할 수 있게 했습니다.

**Q30. 팀에서 본인이 구현한 범위는? (개인 기여 질문)**
> 리포 전체 구조 기준으로 답하면 됩니다 — 분석 파이프라인(ASR·비전·음향·필러), API·인증, 프론트 8개 페이지, i18n(한/영 면접·UI), 보안·컴플라이언스 레이어(암호화·파기·동의·접속기록)가 전부 이 코드베이스 안에 있고, PR 리뷰·회귀 검증 프로세스로 품질을 관리했다고 설명. *(발표 전 팀 내 기여 구분을 정리해 두세요.)*
